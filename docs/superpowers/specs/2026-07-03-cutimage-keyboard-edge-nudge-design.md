# CutImage 单图边框键盘微调设计文档

## 1. 背景

当前单图修正已经支持：

1. 在原图预览中拖拽裁剪框四角或整体移动裁剪框。
2. 在右侧“单图修正”区域手动输入上下左右边界数值。

但在实际使用时，鼠标拖拽有时难以做到像素级精准控制，尤其是在边界只需要轻微调整时，拖拽容易出现“过头”或来回修正的问题。因此需要补充一种更稳定的精调方式。

## 2. 目标

本次新增能力目标如下：

1. 用户可以在原图预览中点击并选中裁剪框的任一边。
2. 选中边之后，可以使用键盘方向键对该边进行像素级微调。
3. 微调后，原图裁剪框、右侧边界输入框、当前裁剪预览、最终拼接预览需要同步刷新。
4. 不破坏当前已有的四角拖拽、整体拖拽、手动输入边界等交互。

## 3. 本次范围

本次只实现键盘微调，不实现鼠标滚轮微调。

本次包含：

1. 原图画布新增四条边的命中与选中状态。
2. 新增方向键微调交互。
3. 新增选中边的轻量视觉高亮。

本次不包含：

1. 鼠标滚轮微调。
2. 纯键盘切换当前选中边。
3. 新增额外工具栏按钮或新的配置项。
4. 修改项目文件存储结构。

## 4. 交互设计

### 4.1 选边规则

当当前图片存在有效裁剪框时，用户在原图画布中点击裁剪框附近区域：

1. 如果命中四个角点，继续保持现有角点拖拽行为优先。
2. 如果未命中角点，但命中四条边中的某一条，则将该边设置为当前选中边。
3. 如果命中矩形内部但未命中边，继续保持现有整体移动逻辑。
4. 如果点击到裁剪框外部空白区域，则清除当前选中边。

### 4.2 键盘微调规则

当满足以下条件时，方向键微调生效：

1. 当前存在项目。
2. 当前选中了某张图片。
3. 当前图片存在有效裁剪框。
4. 当前不处于批量处理中。
5. 当前已经选中某一条边。

方向键规则如下：

1. 选中左边或右边时，只响应 `←` 和 `→`。
2. 选中上边或下边时，只响应 `↑` 和 `↓`。
3. 不匹配当前边方向的按键直接忽略。

步长规则如下：

1. 普通方向键每次移动 `1 px`。
2. `Shift + 方向键` 每次移动 `5 px`。

### 4.3 视觉反馈

原图画布继续保留现有绿色裁剪框和四角控制点。

当某条边被选中时：

1. 使用更亮或更粗的线条重绘该边。
2. 只高亮当前选中的一条边。
3. 切换图片、清除修正、重新批量处理或点击空白区域后，需要清除选边状态。

## 5. 数据与状态设计

本次不修改 `core/models.py` 中的持久化数据结构。

选边状态只作为界面层临时状态存在于 `ui/main_window.py` 中，建议新增：

1. `selected_edge`
   可取值为 `left`、`top`、`right`、`bottom` 或 `None`。

该状态不写入项目文件，不参与保存与恢复。

## 6. 实现设计

### 6.1 命中检测扩展

当前 `_hit_test_rect()` 仅支持：

1. `nw`
2. `ne`
3. `sw`
4. `se`
5. `move`

本次扩展为：

1. 先判断角点命中。
2. 再判断四条边命中：
   `left`、`top`、`right`、`bottom`
3. 最后判断是否命中矩形内部并返回 `move`。

这样可以保证：

1. 原有角点拖拽优先级最高。
2. 点击边时能够稳定进入边选中态。
3. 点击矩形中间区域时仍然可以整体拖动。

### 6.2 键盘事件处理

在 `ui/main_window.py` 中新增统一的键盘事件处理函数，用于：

1. 识别当前是否存在可微调的选中边。
2. 识别当前方向键是否与选中边匹配。
3. 计算步长。
4. 生成新的矩形边界。
5. 调用现有刷新链路更新界面与缓存。

建议将微调后的矩形更新统一收口到一个辅助函数中，避免拖拽修正、手动输入修正和键盘微调各自散落重复逻辑。

### 6.3 矩形约束

键盘微调后生成的新矩形必须满足：

1. 不超出原图边界。
2. 宽度至少为 `1 px`。
3. 高度至少为 `1 px`。

约束可继续复用 `Rect.clamp()` 完成最终边界收缩。

在边靠近极限位置时：

1. 如果继续向外移动，会被限制在图像边界内。
2. 如果继续向内移动导致宽高小于 `1 px`，则保持最小合法矩形，不报错。

### 6.4 刷新链路

每次键盘微调成功后，需要保持和现有拖拽修正一致的刷新结果：

1. 当前图片状态标记为成功。
2. 当前图片消息更新为“手动修正”。
3. 刷新原图画布。
4. 同步右侧四个边界输入框。
5. 更新单张裁剪缓存。
6. 重新计算平均拉伸高度。
7. 刷新最终拼接预览。
8. 刷新左侧图片列表当前项状态。

## 7. 错误处理与兼容性

以下情况直接忽略本次按键，不弹窗：

1. 没有项目。
2. 没有选中图片。
3. 当前图片没有有效裁剪框。
4. 当前没有选中边。
5. 当前处于批量处理中。
6. 当前按键与选中边方向不匹配。

本次不修改项目保存格式，因此：

1. 不影响旧项目打开。
2. 不影响当前项目保存与恢复逻辑。

## 8. 验证点

至少验证以下场景：

1. 点击左边后，`←` / `→` 可以微调左边，`↑` / `↓` 无效。
2. 点击右边后，`←` / `→` 可以微调右边，`↑` / `↓` 无效。
3. 点击上边后，`↑` / `↓` 可以微调上边，`←` / `→` 无效。
4. 点击下边后，`↑` / `↓` 可以微调下边，`←` / `→` 无效。
5. `Shift + 方向键` 步长为 `5 px`。
6. 微调后右侧输入框数值同步变化。
7. 微调后当前裁剪预览同步更新。
8. 微调后最终拼接预览同步更新。
9. 裁剪框贴近图像边缘时不会越界。
10. 裁剪框缩小时不会出现宽高为 `0`。
11. 原有四角拖拽仍正常。
12. 原有整体拖动仍正常。
13. 批量处理中方向键微调无效。

## 9. 改动文件

预计主要修改：

1. `ui/main_window.py`

本次预计不需要修改：

1. `core/models.py`
2. `core/image_processor.py`
3. `core/project_store.py`

## 10. 结论

本次采用“点击选边 + 键盘方向键微调”的方案，为现有单图修正增加稳定的像素级精调能力。

该方案改动集中、风险较低、与当前交互结构兼容性好，适合作为第一阶段精调能力落地；后续如果仍有需要，再考虑补充滚轮微调或更完整的纯键盘修正流程。
