# CutImage 拉伸统一高度自动取平均裁剪高度设计说明

## 1. 背景

当前 CutImage 已支持：

1. `顶部对齐`
2. `居中对齐`
3. `底部对齐`
4. `上下对齐（拉伸）`

并且已经为 `上下对齐（拉伸）` 提供了独立参数：

- `拉伸统一高度`

该参数会同时作用于：

1. GUI 拼接预览
2. `final/combined_result.png`
3. `final/combined_result_target_height.png`

但当前这个参数仍然主要依赖固定值或手工输入。这样会带来一个实际问题：

1. 当当前批次裁剪出来的比色皿整体偏高时，固定值会让结果被压得过扁。
2. 当当前批次裁剪出来的比色皿整体偏矮时，固定值又可能把结果拉得过长。
3. 用户一旦重新批量处理、拖拽修正裁剪框或手动改边界，最合适的拉伸高度其实已经变了。

因此，本次需要让 `拉伸统一高度` 的默认值不再是固定常量，而是自动跟随当前项目中“实际裁剪结果”的平均高度变化。

## 2. 目标

本次改动目标如下：

1. `stretch_target_height` 不再默认固定为常量。
2. 当裁剪结果发生变化时，自动将 `stretch_target_height` 更新为当前所有有效裁剪图高度的平均值。
3. 该平均高度使用四舍五入后的整数。
4. 普通三种对齐模式不受影响。
5. 拉伸模式继续统一使用 `stretch_target_height`。

## 3. 非目标

本次不包含以下内容：

1. 不引入“自动/手动切换”开关。
2. 不改变普通三种对齐模式的高度策略。
3. 不修改导出文件命名、导出目录或项目保存结构。
4. 不修改裁剪识别算法本身。

## 4. 平均高度的定义

### 4.1 数据来源

平均高度基于当前项目中“有效裁剪结果”的高度集合计算。

建议直接使用当前实际用于拼接的数据来源，也就是当前内存中的裁剪结果缓存。

实现上可以理解为：

1. 遍历当前有效的裁剪图
2. 读取每张裁剪图的高度
3. 对这些高度求平均值

### 4.2 取值规则

如果存在至少一张有效裁剪图，则：

1. 计算所有有效裁剪图高度的平均值
2. 对平均值执行四舍五入
3. 最终结果至少为 1

如果当前没有任何有效裁剪图，则：

1. 保持当前 `stretch_target_height` 不变
2. 不做强制覆盖

## 5. 触发时机

本次改动的核心不是“初始化一次”，而是“跟随裁剪结果变化自动刷新”。

因此，以下场景都应触发重新计算平均高度：

1. 批量处理完成后
2. 手动输入边界修正并成功生成新裁剪结果后
3. 拖拽裁剪框修正并成功生成新裁剪结果后
4. 清除手动修正并重新批量处理后

## 6. 行为规则

### 6.1 批量处理

每次批量处理完成后：

1. 程序重新汇总当前所有成功裁剪的图片高度
2. 计算平均值
3. 自动更新 `stretch_target_height`
4. 如果界面当前处于 `上下对齐（拉伸）`，则拼接预览随之刷新

### 6.2 单图手动修正

每次单图边界发生变化并成功更新裁剪结果后：

1. 重新汇总所有当前有效裁剪图高度
2. 重新计算平均高度
3. 自动更新 `stretch_target_height`
4. 刷新最终拼接预览

### 6.3 清除手动修正

清除手动修正会重新走处理链路，因此处理完成后同样应该自动更新平均高度。

## 7. 数据模型与保存

### 7.1 `core/models.py`

`ProcessingSettings` 中的 `stretch_target_height` 字段继续保留，不需要删除。

本次只是改变它的“默认更新来源”：

1. 从原来的固定默认值思路
2. 改为运行时跟随当前裁剪结果自动刷新

### 7.2 项目保存

自动更新后的 `stretch_target_height` 仍然需要正常写入项目文件。

这样做的好处是：

1. 用户重新打开项目时，至少能看到上一次计算出的最近结果
2. 即使还没重新处理，也不会立即回退成无意义的固定值

## 8. 与现有功能的关系

### 8.1 与 `参考高度` 的关系

`参考高度` 继续服务于普通三种对齐模式：

1. 顶部对齐
2. 居中对齐
3. 底部对齐

它不参与本次自动平均逻辑。

### 8.2 与 `上下对齐（拉伸）` 的关系

拉伸模式继续使用 `stretch_target_height`。

本次只是让这个值不再主要依赖固定默认值，而是自动贴近当前这批裁剪结果的平均高度，从而减少过度压扁或拉长。

## 9. 实现建议

建议在 GUI 主逻辑中增加一个专门的小函数，例如“根据当前有效裁剪结果刷新拉伸统一高度”。

这个函数职责应尽量单一：

1. 从当前缓存中收集有效裁剪图高度
2. 计算平均值
3. 更新 `project.settings.stretch_target_height`
4. 同步到界面变量 `stretch_target_height_var`

然后在以下位置复用它：

1. `process_all_images()` 成功处理结束后
2. `apply_manual_rect_from_inputs()` 更新单图裁剪结果后
3. `on_canvas_drag()` 更新单图裁剪结果后
4. `clear_manual_rect()` 触发重新处理后

## 10. 验证方案

建议至少验证以下场景：

1. 一批高度明显不同的裁剪图完成批量处理后，`stretch_target_height` 自动变为它们平均高度。
2. 修改某一张图的裁剪框，使其高度明显变化后，`stretch_target_height` 会自动变化。
3. 清除某一张图的手动修正并重新处理后，`stretch_target_height` 会重新按最新结果计算。
4. 如果当前没有有效裁剪图，`stretch_target_height` 不会被错误改成 0 或空值。
5. 普通三种对齐模式仍然继续使用 `target_height`，不受影响。
6. `上下对齐（拉伸）` 模式下，预览和两张最终图继续统一使用最新的 `stretch_target_height`。

## 11. 验收标准

本次改动完成后，应满足：

1. `stretch_target_height` 默认会跟随当前有效裁剪结果自动更新。
2. 更新依据为“当前有效裁剪图高度的平均值”。
3. 重新批量处理、手动改边界、拖拽修正、清除手动修正后都会重新计算。
4. 计算结果为四舍五入后的整数。
5. 普通三种对齐模式行为不变。
6. 拉伸模式不再容易因为固定默认值而出现明显过扁变形。

## 12. 实施结论

本次需求最合适的实现方式，是让 `stretch_target_height` 在每次裁剪结果变化后自动回到“当前有效裁剪图平均高度”。

这样做的优点是：

1. 不需要增加新的参数或开关。
2. 行为贴合当前实际数据，而不是依赖固定常量。
3. 当用户手动修正裁剪框后，拉伸高度会自然跟着变化。
4. 可以明显降低 `上下对齐（拉伸）` 模式下“被压得太扁”的概率。
