# CutImage 比色皿上半部分补齐实验设计说明

## 1. 背景

当前 CutImage 已经能够稳定完成比色皿区域识别、单张裁剪、结果拼接、项目保存与导出。  
但现阶段实际拍摄到的比色皿图片通常只包含下半部分，而业务上希望最终结果图中的比色皿看起来更接近完整形态，也就是在顶部补出一段标准化的“上半部分”。

这次需求的重点不是修改现有成功流程，而是在不影响主产品的前提下，新增一个完全隔离的实验方案，用于验证“补齐上半部分”是否可行、效果是否自然、后续是否值得并入正式产品。

## 2. 目标

本次实验设计需要满足以下目标：

1. 验证比色皿上半部分补齐在视觉上是否可行。
2. 第一阶段仅作用于最终拼接图，不改变现有单张裁剪结果与单张导出结果。
3. 所有实验代码、参数、样例与输出都放在独立目录中。
4. 删除实验目录后，本次新增能力应整体消失，当前成功版本的主程序不受影响。
5. 方案应尽量容易实现、容易调参、容易观察效果。

## 3. 范围

### 3.1 本次范围

1. 新建独立实验目录 `_top_extension_experiment/`。
2. 在实验目录中实现“模板式补齐上半部分”的实验逻辑。
3. 第一阶段只针对最终拼接图的视觉结果做补齐。
4. 支持通过配置参数调整补齐高度、顶部内弧深度、侧壁宽度、融合高度等。
5. 生成实验输出图，用于人工对比效果。

### 3.2 暂不纳入范围

1. 不修改 `app.py`。
2. 不修改 `run_cutimage.bat`。
3. 不把实验功能接入现有 GUI。
4. 不改变单张裁剪预览。
5. 不改变单张裁剪图导出。
6. 不改变现有项目文件结构与保存逻辑。
7. 不尝试恢复每张图片真实缺失的上半部分细节。
8. 不引入 AI 补图、图像生成模型或复杂配准流程。

## 4. 方案选择

围绕“补齐上半部分”，当前可以考虑三类路线：

1. 模板式补齐
2. 基于当前图片做延展补齐
3. 基于完整参考图做配准补齐

本次实验选择第 1 条路线：模板式补齐。

选择原因如下：

1. 当前图片缺失位置比较稳定，适合使用统一模板。
2. 模板式补齐实现难度最低，最适合作为第一轮验证。
3. 它可以在不破坏现有识别与裁剪链路的前提下工作。
4. 即使效果不理想，也只会影响实验目录中的输出，不会污染主产品。

## 5. 总体思路

本次实验不试图“复原真实上半部分”，而是生成一段规则化、标准化、视觉上像完整比色皿头部的模板结构，并将其与当前下半部分图像在顶部拼接。

整体思路如下：

1. 保留现有裁剪逻辑与现有下半部分真实图像。
2. 在每张图顶部额外增加一段模板头部区域。
3. 模板头部由程序绘制，主要表现比色皿的玻璃边框、顶部黑色空腔和底部圆弧。
4. 在模板头部与原始下半部分的连接区域使用渐变融合，减少“硬贴上去”的感觉。
5. 将补齐后的单张结果再用于实验版最终拼接图输出。

## 6. 实验目录设计

建议新增独立目录：

- `_top_extension_experiment/`

建议目录结构如下：

- `_top_extension_experiment/README.md`
- `_top_extension_experiment/config.json`
- `_top_extension_experiment/experiment_runner.py`
- `_top_extension_experiment/top_extension_renderer.py`
- `_top_extension_experiment/sample_input/`
- `_top_extension_experiment/sample_output/`
- `_top_extension_experiment/debug_output/`

各文件或目录职责如下：

### 6.1 `experiment_runner.py`

负责组织整个实验流程：

1. 读取实验配置。
2. 加载测试输入图像。
3. 调用补齐渲染逻辑。
4. 生成补齐后的单张结果或最终拼接结果。
5. 将实验结果输出到 `sample_output/`。

### 6.2 `top_extension_renderer.py`

只负责补齐算法本身：

1. 生成顶部模板头部。
2. 计算与原图宽度匹配的结构参数。
3. 完成顶部与原图的融合。
4. 返回补齐后的 RGB 图像。

### 6.3 `config.json`

负责存储实验参数，避免每次改代码试参数。

### 6.4 `sample_input/`

放置用于验证的一组样例图片。  
建议优先使用当前已经裁剪成功、且缺失位置稳定的样例。

### 6.5 `sample_output/`

输出实验结果图，用于观察最终效果。

### 6.6 `debug_output/`

可选输出中间过程图，如：

1. 头部模板图
2. 融合遮罩图
3. 拼接前后对比图

## 7. 隔离原则

本次实验必须严格满足以下隔离规则：

1. 主程序入口不 import 实验目录中的模块。
2. 现有 GUI 不增加任何实验按钮、实验参数或实验预览。
3. 现有导出按钮不触发实验逻辑。
4. 现有项目文件中不保存实验参数。
5. 实验目录仅作为独立脚本与独立产物存在。

在此约束下，只要删除 `_top_extension_experiment/`，则：

1. 实验逻辑消失。
2. 实验参数消失。
3. 实验输出消失。
4. 主程序仍按当前成功版本继续运行。

## 8. 补齐算法设计

### 8.1 输入假设

基于当前用户反馈，本次实验建立如下输入假设：

1. 当前图片主要缺失比色皿上半部分。
2. 缺失高度在同一批图片中基本稳定。
3. 图片主体位置相对规整，便于使用统一模板补齐。

### 8.2 结果定位

本次补齐结果的目标是：

1. 让最终拼接图里的单个比色皿看起来更完整。
2. 追求整体观感自然，而不是逐张真实复原。
3. 优先保证稳定性，其次再追求细节逼真度。

### 8.3 模板头部的组成

模板头部建议包含以下视觉元素：

1. 左侧玻璃外边线
2. 右侧玻璃外边线
3. 顶部外框横向边
4. 内部黑色空腔
5. 空腔底部圆弧
6. 空腔下沿的高光带
7. 与下半部分液体或发光区域过渡的融合层

### 8.4 补齐流程

建议按以下流程处理单张图：

1. 输入当前真实裁剪图 `crop_rgb`。
2. 根据图像宽度和配置参数，计算补齐头部的高度与各结构宽度。
3. 新建一张高度更高的结果画布。
4. 在画布顶部绘制模板头部。
5. 将原始 `crop_rgb` 放到模板头部下方。
6. 在连接区域执行纵向渐变融合。
7. 输出补齐后的新图。

### 8.5 模板绘制方式

建议采用纯规则绘制，而不是贴图式拷贝。  
原因如下：

1. 规则绘制不依赖固定参考图。
2. 规则绘制更容易适配不同宽度。
3. 规则绘制更容易后续调参。
4. 规则绘制更适合做第一轮快速实验。

可使用的基础图形包括：

1. 矩形
2. 圆角矩形
3. 椭圆弧
4. 线性渐变
5. 透明度遮罩

### 8.6 融合策略

模板头部与真实下半部分之间不建议做硬切。  
建议增加一段可调的融合区 `blend_height`，在这段区域中：

1. 模板头部向下逐渐减弱。
2. 原始下半部分向下逐渐增强。
3. 最终形成平滑过渡。

这样做的目标是尽量隐藏拼接边界。

## 9. 参数设计

建议在实验配置中提供以下参数：

1. `enabled`
   是否启用顶部补齐。
2. `extension_height`
   模板头部总高度。
3. `inner_arc_depth`
   顶部黑色空腔底部圆弧下凹深度。
4. `side_wall_width`
   左右玻璃边宽度。
5. `top_border_height`
   顶部外框厚度。
6. `blend_height`
   与原图融合的高度。
7. `highlight_strength`
   头部高光强度。
8. `highlight_width`
   高光带宽度。

第一版建议只暴露前 5 个主要参数即可，剩余参数可保留默认值写死在代码中。

## 10. 数据流设计

本次实验建议采用独立数据流，不接入主程序流程。

建议流程如下：

1. 从 `sample_input/` 读取测试图。
2. 使用实验脚本生成“补齐后的单张结果”。
3. 如果需要，可在实验脚本中将补齐后的单张结果再次横向拼接。
4. 输出到 `sample_output/` 供人工观察。

如果希望更贴近现有主产品的效果，也可以在实验脚本中只复用现有只读函数，例如：

1. 读取图片
2. 现有裁剪结果的后处理
3. 现有最终拼接逻辑

但实验代码不应反向改动主代码。

## 11. 与主产品的关系

本次实验与主产品的关系应明确为“旁路验证”而非“主链路升级”。

具体要求：

1. 主产品继续保持现在的成功行为。
2. 实验版只额外生成一套对比结果。
3. 实验版成功后，再决定是否写第二份正式设计文档，将其并入主产品。

## 12. 验证方式

建议至少准备以下几类验证：

### 12.1 视觉完整性验证

检查补齐后是否达到“像完整比色皿”的直观观感，包括：

1. 顶部结构是否完整
2. 左右边壁是否连续
3. 顶部黑色空腔是否自然
4. 底部与原图连接是否突兀

### 12.2 稳定性验证

对同一批多张图运行实验，观察：

1. 是否每张都能生成结果
2. 是否存在明显错位
3. 是否存在某些图的顶部比例明显不对

### 12.3 参数可调性验证

至少验证以下参数变化是否符合预期：

1. `extension_height`
2. `inner_arc_depth`
3. `side_wall_width`
4. `blend_height`

### 12.4 回退验证

验证以下场景：

1. 删除 `_top_extension_experiment/` 后，主程序依然正常运行。
2. 当前已有项目、预览、导出和保存流程不受影响。

## 13. 风险与限制

本次方案存在以下天然限制：

1. 生成的是标准化头部，而不是真实缺失内容。
2. 如果不同图片的缺失高度不再稳定，统一模板效果会下降。
3. 如果原图宽度差异较大，某些参数可能需要按比例推导，而不能直接固定。
4. 如果原图顶部残留结构太多，模板与真实内容可能会冲突。

这些限制是可接受的，因为本次目标本来就是做第一轮低风险验证。

## 14. 后续演进方向

如果模板式补齐实验结果较好，后续可以考虑以下升级路线：

1. 把参数推导做得更自动，减少手动调节。
2. 基于当前图像顶部边缘信息，自动微调模板的内弧位置。
3. 增加“参考完整图配准”的第二实验版本。
4. 在验证稳定后，再设计如何以可选开关形式并入主产品 GUI。

## 15. 验收标准

本次实验完成后，至少满足以下标准：

1. 存在独立实验目录 `_top_extension_experiment/`。
2. 主程序代码路径不受影响。
3. 能生成一批带顶部补齐效果的实验结果图。
4. 用户可以通过少量参数调整补齐外观。
5. 删除实验目录后，主程序仍可按当前方式正常运行。

## 16. 实施顺序建议

建议按以下顺序推进：

1. 创建 `_top_extension_experiment/` 目录与基础文件。
2. 实现单张图顶部模板补齐。
3. 输出单张调试结果。
4. 输出实验版最终拼接图。
5. 调整默认参数，使第一版结果达到“基本自然”。
6. 再决定是否进入主产品集成设计。
