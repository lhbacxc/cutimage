# CutImage 仓库发布与 .gitignore 设计说明

## 1. 目标

本次整理的目标是将 `CutImage` 项目发布到 GitHub 远端仓库，同时控制仓库内容范围，避免把本地缓存、历史验证产物和已完成的中文测试目录一并提交。

## 2. 收录原则

仓库中保留以下内容：

1. 核心源码：
   `app.py`、`core/`、`ui/`
2. 启动脚本：
   `run_cutimage.bat`
3. 项目文档与设计说明：
   `docs/`
4. 仍有参考价值的实验源码与说明文件：
   例如 `_top_extension_experiment/` 中的 `.py`、`.md`、`.bat`、`.json`

## 3. 忽略原则

以下内容不进入 Git 仓库：

1. Python 缓存文件：
   `__pycache__/`、`*.pyc`、`*.pyo`
2. Windows 与 macOS 常见系统临时文件：
   `Thumbs.db`、`.DS_Store`
3. 本地项目存档文件：
   `*.cutimage.json`
4. 本地导出结果：
   `cropped/`、`final/` 目录中的导出图，以及验证目录中的结果图
5. 已完成的中文路径验证目录：
   `中文测试/`
6. 本地原始样例图片：
   `image/` 目录与仓库根目录下的 `IMG*.jpg`、`IMG*.jpeg`

## 4. 设计取舍

本次不采用“忽略所有以下划线开头目录”的粗暴策略，因为那会误伤实验源码与说明文件。

本次采用“按文件类型与导出目录精确忽略”的策略，使仓库保留开发所需的代码与文档，同时排除体积大、复现价值低、会持续变化的本地结果文件。

## 5. 发布流程

1. 创建 `.gitignore`
2. 由用户审阅忽略规则
3. 初始化本地 Git 仓库
4. 提交首个版本
5. 关联远端仓库 `lhbacxc/cutimage`
6. 推送到 GitHub
