# CutImage 拉伸统一高度独立控制设计说明

## 1. 背景

当前 CutImage 已经新增了第 4 种对齐模式：

1. 顶部对齐
2. 居中对齐
3. 底部对齐
4. 上下对齐（拉伸）

其中 `上下对齐（拉伸）` 的目标是让所有参与拼接的比色皿在最终结果中同时满足：

1. 顶部对齐
2. 底部对齐
3. 过短图被拉长
4. 过长图被压扁

但在当前实现中，拉伸模式复用了已有的 `参考高度` 参数，导致两个问题：

1. 普通三种对齐模式和拉伸模式共用同一个高度参数，语义不够清晰。
2. 用户在普通模式下觉得预览合适的 `参考高度`，切到拉伸模式后不一定仍然合适，容易出现“拉伸后太扁”或“拉伸后太高”的情况。

因此，本次需要把“拉伸模式使用的统一高度”从现有 `参考高度` 中独立出来，形成一个专门服务于 `上下对齐（拉伸）` 的新参数。

## 2. 目标

本次改动目标如下：

1. 新增一个独立参数：`拉伸统一高度`。
2. 该参数只在 `上下对齐（拉伸）` 模式下生效。
3. 普通三种对齐模式继续使用现有 `参考高度` 逻辑，不受影响。
4. `上下对齐（拉伸）` 下的三条链路统一使用这个新参数：
   - GUI 拼接预览
   - `final/combined_result_target_height.png`
   - `final/combined_result.png`
5. 旧项目加载时保持兼容，不因缺少新字段而报错。

## 3. 非目标

本次不包含以下内容：

1. 不修改自动识别和单张裁剪逻辑。
2. 不影响 `cropped/` 单张裁剪图导出。
3. 不移除现有 `参考高度` 参数。
4. 不改变四种对齐模式的名称和基本语义。
5. 不新增额外的拉伸比例、宽高比锁定等更复杂选项。

## 4. 参数设计

### 4.1 现有参数

保留现有参数：

- `参考高度`

该参数继续用于：

1. 顶部对齐
2. 居中对齐
3. 底部对齐

在这些模式下，程序仍然按照当前逻辑进行等比缩放拼接预览和缩略导出。

### 4.2 新增参数

新增参数：

- `拉伸统一高度`

该参数只在 `上下对齐（拉伸）` 模式下生效，表示所有参与拼接的单张图在进入拼接前，统一被拉伸或压缩到的目标高度。

建议默认值：

- 与当前 `参考高度` 相同

这样旧项目在首次加载新版本时，不会因为新增参数而出现突兀变化。

## 5. 用户可见行为

### 5.1 GUI 展示

在右侧全局参数区新增一项：

- `拉伸统一高度`

建议放在 `参考高度` 附近，便于用户理解两者都是“拼接相关高度参数”，但服务于不同模式。

### 5.2 启用规则

当对齐模式为：

1. `顶部对齐`
2. `居中对齐`
3. `底部对齐`

则：

- `拉伸统一高度` 输入框置灰

当对齐模式为：

- `上下对齐（拉伸）`

则：

- `拉伸统一高度` 输入框启用

这样可以明确告诉用户：只有拉伸模式才会读取这个参数。

### 5.3 四种模式的高度来源

1. `顶部对齐`
   拼接预览与缩略导出继续使用 `参考高度`。
2. `居中对齐`
   拼接预览与缩略导出继续使用 `参考高度`。
3. `底部对齐`
   拼接预览与缩略导出继续使用 `参考高度`。
4. `上下对齐（拉伸）`
   拼接预览、缩略导出、主结果图统一使用 `拉伸统一高度`。

## 6. 数据模型设计

### 6.1 `core/models.py`

在 `ProcessingSettings` 中新增字段：

- `stretch_target_height`

建议：

1. 类型保持整数。
2. 默认值与 `target_height` 一致。
3. 写入项目文件时一并保存。

### 6.2 旧项目兼容

当加载旧项目时，如果缺少 `stretch_target_height`，则使用以下回退策略：

1. 先读取旧项目中的 `target_height`
2. 用该值作为 `stretch_target_height` 的默认值

这样旧项目在新版本中切换到拉伸模式时，初始行为与当前版本尽量接近。

## 7. 拼接逻辑设计

### 7.1 普通三种对齐

当 `align_mode` 为：

1. `top`
2. `center`
3. `bottom`

则保持当前逻辑不变：

1. `target_height` 链路继续按 `target_height` 做等比缩放
2. `original` 链路继续保留原始裁剪高度
3. 通过纵向偏移实现顶部、居中、底部三种对齐

### 7.2 拉伸模式

当 `align_mode` 为：

- `stretch`

则三条链路都改为统一使用 `stretch_target_height`：

1. GUI 拼接预览
   所有图拉伸或压缩到 `stretch_target_height`
2. `combined_result_target_height.png`
   所有图拉伸或压缩到 `stretch_target_height`
3. `combined_result.png`
   所有图也拉伸或压缩到 `stretch_target_height`

这意味着拉伸模式下不再区分：

1. `target_height` 链路
2. `original` 链路

在高度来源上的差异。

两条导出链路仍然保留不同文件名和现有导出结构，但它们在拉伸模式下会共享同一套统一高度参数。

### 7.3 拉伸方式

继续沿用现有拉伸模式策略：

1. 只改高度
2. 保持宽度不变
3. 使用插值重采样

也就是：

1. 输出宽度 = 原宽度
2. 输出高度 = `stretch_target_height`

## 8. 预览与导出一致性

本次需要重点保证以下一致性：

1. GUI 拼接预览看到的拉伸高度
2. `combined_result_target_height.png` 的拉伸高度
3. `combined_result.png` 的拉伸高度

三者应完全一致，避免用户在界面里看到一个比例，导出后得到另一个比例。

## 9. 交互细节

建议同步补充以下细节：

1. 当切换对齐模式时，立即刷新 `拉伸统一高度` 输入框的可编辑状态。
2. 当用户修改 `拉伸统一高度` 后，刷新拼接预览。
3. 当项目加载完成时，根据当前 `align_mode` 恢复输入框启用或置灰状态。

## 10. 验证方案

建议至少验证以下场景：

1. 旧项目文件可以正常打开，不因缺少 `stretch_target_height` 出错。
2. 新建项目时，`拉伸统一高度` 默认值与 `参考高度` 一致。
3. 当对齐模式不是 `上下对齐（拉伸）` 时，`拉伸统一高度` 输入框置灰。
4. 当切换到 `上下对齐（拉伸）` 时，`拉伸统一高度` 输入框启用。
5. 修改 `拉伸统一高度` 后，拼接预览立即变化。
6. `上下对齐（拉伸）` 下，`combined_result_target_height.png` 与预览高度一致。
7. `上下对齐（拉伸）` 下，`combined_result.png` 也使用相同的拉伸统一高度。
8. 普通三种对齐模式的预览与导出行为不变。
9. `cropped/` 单张裁剪图仍保持不变。

## 11. 验收标准

本次改动完成后，应满足：

1. GUI 中存在独立的 `拉伸统一高度` 参数。
2. 该参数只在 `上下对齐（拉伸）` 模式下生效。
3. 普通三种对齐模式继续按 `参考高度` 工作。
4. 拉伸模式下，拼接预览、`combined_result_target_height.png` 和 `combined_result.png` 使用同一个拉伸统一高度。
5. 旧项目可以正常加载和继续保存。
6. 其它既有功能不受影响。

## 12. 实施结论

本次需求最合理的实现方式，是在保留 `参考高度` 的前提下，新增一个专门服务于 `上下对齐（拉伸）` 的 `stretch_target_height` 参数。

这样做的优点是：

1. 普通模式与拉伸模式职责清晰。
2. 用户能单独调节拉伸后的最终观感。
3. 预览与导出可以统一吃同一参数，降低理解成本。
4. 对当前项目结构改动有限，兼容成本较低。
