# CutImage 桌面工具设计说明

## 1. 背景

当前项目需要将一组包含发光比色皿的原始图片进行批量处理，自动提取目标区域，按顺序拼接为最终结果图。同时，工具需要支持后续重复使用，避免每次都手动修改脚本和参数。

## 2. 目标

本次实现的目标是提供一个本地桌面小程序，满足以下需求：

1. 导入一个图片文件夹并自动读取其中的原始图片。
2. 自动识别每张图片中的目标区域并完成裁剪。
3. 支持对识别结果进行人工修正。
4. 支持自动排序和手动调整图片顺序。
5. 生成最终拼接图，并保存单张裁剪图。
6. 保存项目配置，便于后续重新打开继续编辑。

## 3. 范围

### 3.1 本次范围

1. 使用 Python 实现本地桌面程序。
2. 使用 OpenCV 完成图像识别、裁剪、缩放与拼接。
3. 使用轻量图形界面框架构建单窗口桌面程序。
4. 支持项目保存、重新打开、再次导出。

### 3.2 暂不纳入范围

1. 云端同步或多人协作。
2. 复杂图像增强算法，如自动去噪、颜色校正、透视校正。
3. 安装包制作和自动更新机制。
4. 多项目标签页或多窗口并行编辑。

## 4. 总体方案

采用“轻量界面 + 分层处理核心”的实现方式：

1. 界面层负责项目操作、图片列表、参数调节、预览展示、手动修正与导出触发。
2. 处理层负责原图读取、目标检测、裁剪、统一尺寸、拼接和结果输出。
3. 项目存储层负责保存项目配置、排序结果、单图修正数据和导出配置。

第一版界面使用 `Tkinter`，图像处理使用 `OpenCV + Pillow + NumPy`。这样可以在较低复杂度下尽快交付一个可重复使用的桌面工具，同时保留后续升级界面的空间。

## 5. 用户流程

### 5.1 新建项目

1. 用户启动程序。
2. 用户点击“新建项目”并选择原图文件夹。
3. 程序读取用户指定目录中的图片文件。
4. 程序按文件名自动排序并生成缩略图列表。

### 5.2 批量处理

1. 用户调整全局参数。
2. 用户点击“批量处理”。
3. 程序自动识别每张图的目标区域并生成裁剪结果。
4. 程序生成单张预览和整体拼接预览。

### 5.3 人工修正

1. 用户在左侧列表中选择某一张图片。
2. 程序展示原图和当前裁剪框。
3. 用户拖动裁剪框，或通过上下左右边界微调修正结果。
4. 程序保存该图的手动修正结果，并优先覆盖自动识别结果。

### 5.4 导出结果

1. 用户确认排序、参数和单图修正结果。
2. 用户点击“导出”。
3. 程序输出最终拼接图、单张裁剪图和项目配置文件。

### 5.5 打开已有项目

1. 用户打开已有项目文件。
2. 程序恢复原图列表、排序状态、全局参数和单图修正数据。
3. 用户可以继续调整并重新导出。

## 6. 界面设计

程序采用单窗口三栏布局：

### 6.1 左侧栏

用于展示图片缩略图列表和顺序控制：

1. 原图缩略图列表。
2. 当前选中状态。
3. 上移、下移等顺序调整按钮。
4. 自动排序恢复按钮。
5. 异常图片状态标记。

### 6.2 中间区域

用于展示可视化内容：

1. 当前选中图片的原图预览。
2. 自动或手动裁剪框叠加显示。
3. 裁剪结果预览。
4. 最终拼接结果预览。

### 6.3 右侧栏

用于参数、项目和导出控制：

1. 全局参数配置区。
2. 单图修正控制区。
3. 项目保存与打开按钮。
4. 批量处理按钮。
5. 导出按钮。
6. 日志与异常提示区域。

## 7. 处理算法设计

### 7.1 自动检测流程

1. 读取原图。
2. 转换为灰度图。
3. 对灰度图执行阈值分割。
4. 查找外部轮廓。
5. 选择面积最大的有效轮廓作为目标区域。
6. 根据轮廓外接矩形生成裁剪框。
7. 在裁剪框四周增加可配置的 `padding`。

### 7.2 批量输出流程

1. 对每张图生成最终裁剪框。
2. 裁剪得到单张结果图。
3. 按统一高度策略缩放所有裁剪结果。
4. 根据设定间距和背景色生成拼接结果图。
5. 输出单张图和最终拼接图。

### 7.3 手动修正策略

1. 先生成自动裁剪结果。
2. 如果用户手动修正，则记录当前图片的最终裁剪框。
3. 重新处理时优先读取手动修正结果。
4. 用户可以撤销单张手动修正，恢复自动识别结果。

## 8. 参数设计

第一版建议支持以下全局参数：

1. 二值化阈值。
2. 裁剪外扩 `padding`。
3. 最终统一高度策略。
4. 图片间距。
5. 拼接背景色。
6. 输出图片格式。

单图级别支持以下参数：

1. 当前图片最终裁剪框。
2. 是否启用手动修正。

## 9. 项目文件设计

项目文件使用结构化文本格式保存，建议采用 `JSON`。项目内容包括：

1. 项目名称。
2. 原图目录相对路径。
3. 当前图片排序结果。
4. 全局参数。
5. 每张图片的自动检测结果。
6. 每张图片的手动修正结果。
7. 当前输出目录设置。
8. 最近一次导出结果信息。

路径记录策略明确如下：

1. 项目文件中的目录字段统一保存为相对于项目文件所在目录的相对路径。
2. 单张图片记录使用文件名列表，不重复保存绝对路径。
3. 项目文件的作用是恢复编辑状态，而不是替代原始图片本身。
4. 原图仍以外部文件形式保存在用户选择的原图目录中。

## 10. 输出目录设计

导出时建议生成如下目录结构：

```text
输出目录/
  项目名/
    cropped/
    final/
    project/
```

说明如下：

1. `cropped/` 保存单张裁剪结果。
2. `final/` 保存最终拼接图。
3. `project/` 保存项目配置文件副本，便于归档。

## 11. 模块划分

建议按以下职责拆分代码：

1. `app.py`：程序入口。
2. `ui/`：界面组件、布局与事件处理。
3. `core/image_processor.py`：自动识别、裁剪、缩放与拼接逻辑。
4. `core/project_store.py`：项目加载、保存与路径处理。
5. `core/models.py`：项目数据结构定义。
6. `utils/`：通用工具函数。

该拆分方式可以保证界面代码与图像处理代码解耦，方便后续维护和扩展。

## 12. 异常处理

程序应遵循“单图失败不影响整批继续”的原则，至少处理以下异常：

1. 图片无法读取。
2. 未识别到有效目标区域。
3. 手动裁剪框越界。
4. 项目文件损坏或字段缺失。
5. 项目引用的原图缺失。
6. 导出目录不可写。

异常处理要求：

1. 在界面中显示明确错误原因。
2. 在列表中标记异常图片。
3. 不因单张图片失败而导致程序整体退出。
4. 保留日志信息，方便排查。

## 13. 验收标准

以下标准全部满足后，可认为第一版达到目标：

1. 程序可正常启动并显示主界面。
2. 可以新建项目并导入图片文件夹。
3. 可以自动识别目标区域并生成裁剪结果。
4. 可以预览裁剪结果和最终拼接结果。
5. 可以修改全局参数并重新处理。
6. 可以手动调整单张图片的裁剪框。
7. 可以调整图片顺序并重新生成拼接结果。
8. 可以保存项目并在重新打开后恢复状态。
9. 可以导出最终拼接图、单张裁剪图和项目配置文件。
10. 存在异常图片时，程序仍能继续处理剩余图片。

## 14. 实施建议

实施时建议按以下顺序推进：

1. 先完成图像处理核心模块。
2. 再完成项目文件读写。
3. 然后搭建基础桌面界面。
4. 最后补齐手动修正、预览刷新和导出流程。

该顺序可以先确保算法闭环，再逐步叠加交互能力，降低联调复杂度。
