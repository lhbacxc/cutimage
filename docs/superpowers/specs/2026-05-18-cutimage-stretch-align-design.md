# CutImage 上下对齐拉伸模式设计说明

## 1. 背景

当前 CutImage 的最终拼接图支持三种纵向对齐方式：

1. 顶部对齐
2. 居中对齐
3. 底部对齐

这三种模式本质上都只是决定单张图片在拼接画布中的纵向摆放位置，并不会改变单张图片本身的高度。

因此，当同一批比色皿裁剪结果的高度本来就不一致时，即使选择顶部对齐或底部对齐，也只能保证其中一个边界对齐，另一侧仍然会出现参差不齐的情况。

当前用户希望得到的新效果不是“只改摆放位置”，而是让最终拼接图中的所有比色皿在视觉上具有统一高度，也就是：

1. 顶部对齐
2. 底部也对齐
3. 过短的图被纵向拉长
4. 过长的图被纵向压缩

换句话说，这次需要新增一种“统一高度后再拼接”的模式，而不是继续沿用现有三种仅偏移不变形的对齐模式。

## 2. 目标

本次改动目标如下：

1. 在现有三种对齐方式基础上，新增第 4 种模式：`上下对齐（拉伸）`。
2. 该模式只影响拼接预览与最终拼接图。
3. `cropped/` 目录中的单张裁剪图保持原始裁剪高度，不参与这次拉伸或压缩。
4. 新模式下所有参与拼接的单张图都被强制调整到统一高度，从而实现顶部和底部同时对齐。
5. 保持现有背景色、圆角、白底细边框、间距、双产物导出逻辑不变。

## 3. 非目标

本次不包含以下内容：

1. 不修改自动识别裁剪框逻辑。
2. 不修改单张裁剪图导出尺寸。
3. 不新增额外开关或独立面板。
4. 不移除现有 `顶部对齐`、`居中对齐`、`底部对齐` 三种模式。
5. 不改变 `combined_result.png` 与 `combined_result_target_height.png` 的文件命名与导出路径。

## 4. 用户可见行为

### 4.1 新增模式

在 GUI 的“对齐”下拉框中，新增一个选项：

- `上下对齐（拉伸）`

保留原有选项：

- `顶部对齐`
- `居中对齐`
- `底部对齐`

### 4.2 模式语义

各模式行为定义如下：

1. `顶部对齐`
   仅控制纵向偏移，图片原高度不变。
2. `居中对齐`
   仅控制纵向偏移，图片原高度不变。
3. `底部对齐`
   仅控制纵向偏移，图片原高度不变。
4. `上下对齐（拉伸）`
   不再通过纵向偏移解决高度差，而是将每张图直接调整为统一高度后再拼接，因此顶部和底部天然同时对齐。

## 5. 统一高度规则

### 5.1 对 `target_height` 拼接的规则

`target_height` 模式当前用于：

1. GUI 拼接预览
2. `final/combined_result_target_height.png`

在新模式下，这一链路中的统一高度直接取：

- `settings.target_height`

也就是每张参与拼接的图片都被处理成：

- 输出高度 = `target_height`

### 5.2 对 `original` 拼接的规则

`original` 模式当前用于：

1. `final/combined_result.png`

该图目前保留原始裁剪分辨率，不按 `target_height` 缩小。

为了让这一主结果图在新模式下仍然满足“顶部和底部都对齐”，统一高度应取当前批次参与拼接图片中的最大原始高度，也就是：

1. 先统计所有裁剪图原始高度
2. 取其中最大值作为拼接统一高度
3. 过短图向上拉伸到该高度
4. 过长图理论上不会出现，因为基准已经取最大值

说明：

虽然用户表达中包含“过长压扁”，但在 `original` 主结果图链路下，如果以当前批次最大高度作为统一值，则不会发生向下压缩，只会对较短图片做拉伸。

这与当前“主结果图尽量保留更多原始细节”的设计方向是一致的，也能避免把原本最高的图片反而压矮。

## 6. 拉伸策略

本次“上下对齐（拉伸）”采用以下策略：

1. 只改变图片高度
2. 保持图片宽度不变
3. 使用重采样算法对纵向像素进行插值

也就是对单张图执行“纵向非等比缩放”：

1. 输出宽度 = 原宽度
2. 输出高度 = 统一高度

这样可以精确实现用户所说的：

1. 过短的拉长
2. 过长的压扁

并且不会引入横向宽度变化，避免同一批比色皿因为统一高度而出现整体变胖或变瘦的副作用。

## 7. 实现设计

### 7.1 `ui/main_window.py`

需要修改：

1. 在 `ALIGN_LABELS` 中新增中文标签到内部值的映射。
2. 让“对齐”下拉框显示新的第 4 种模式。
3. 项目加载时能够正确回显该模式。
4. 参数变更后继续沿用现有刷新预览逻辑。

建议新增映射值：

- 中文标签：`上下对齐（拉伸）`
- 内部值：`stretch`

### 7.2 `core/models.py`

`ProcessingSettings.align_mode` 当前已经是字符串字段，因此无需新增独立字段。

只需要保证：

1. 新项目可以保存 `stretch`
2. 旧项目继续兼容 `top` / `center` / `bottom`
3. 读取未知值时仍然安全回退

### 7.3 `core/image_processor.py`

当前 `build_final_image()` 的核心流程是：

1. 根据 `size_mode` 决定是否按统一比例缩放
2. 统计内容总宽和最大高度
3. 根据 `align_mode` 计算每张图的纵向偏移
4. 贴到最终画布上

本次需要在这条链路中新增 `stretch` 分支。

建议行为如下：

1. 如果 `align_mode` 不是 `stretch`
   保持现有逻辑不变。
2. 如果 `align_mode` 是 `stretch`
   则不再为每张图计算不同的 `offset_y`。
3. 而是在贴图前就把每张图处理成统一高度。

统一高度建议按 `size_mode` 决定：

1. `target_height`
   统一高度 = `settings.target_height`
2. `original`
   统一高度 = 当前批次最大原始高度

贴图时：

1. `content_height` 直接等于统一高度
2. 每张图的 `offset_y` 固定为 0
3. 外层仍然叠加现有 `outer_padding`

### 7.4 样式处理顺序

建议顺序保持为：

1. 先生成拼接所需尺寸的单张输出图
2. 再应用最终图形状样式
3. 最后贴到总画布上

这样可以保证：

1. 圆角基于最终尺寸计算
2. 白底细边框围绕最终尺寸绘制
3. 新模式不会破坏既有视觉样式

## 8. 兼容性与边界

### 8.1 旧项目兼容

旧项目配置中没有 `stretch` 值，因此保持原样即可，不需要迁移。

### 8.2 空数据保护

如果没有可拼接图片，仍然沿用现有错误提示：

- 没有可用于拼接的图片

### 8.3 极小高度保护

统一高度计算时仍需保证最小值至少为 1，避免出现非法 resize 尺寸。

### 8.4 预览与导出一致性

GUI 拼接预览当前对应 `target_height` 版本。

因此在新模式下应保证：

1. 预览使用 `target_height` 统一高度
2. 缩略导出图使用同一规则
3. 主结果图使用 `original` 链路下的统一高度规则

## 9. 验证方案

建议至少验证以下场景：

1. 三张高度明显不同的裁剪图，在 `顶部对齐` 下仍然只有顶部对齐，底部参差。
2. 切换到 `上下对齐（拉伸）` 后，三张图顶部和底部都齐平。
3. GUI 拼接预览与 `combined_result_target_height.png` 结果一致。
4. `combined_result.png` 在新模式下也达到统一高度。
5. `cropped/` 单张裁剪图尺寸保持不变。
6. 圆角模式下新模式仍正常输出。
7. 白底细边框模式下新模式仍正常输出。
8. 旧项目文件重新打开后仍能正常加载并导出。

## 10. 验收标准

本次改动完成后，应满足：

1. GUI 中可选择 `上下对齐（拉伸）`。
2. 该模式下拼接预览中的所有比色皿高度一致。
3. 该模式下最终拼接图中的所有比色皿顶部和底部都对齐。
4. `cropped/` 单张图导出不受影响。
5. 原有三种对齐模式行为不变。
6. 双产物导出、圆角、白底细边框、背景色、间距逻辑继续正常工作。

## 11. 实施结论

本次需求最合适的落点，是在现有“对齐”体系中新增一个 `stretch` 模式，而不是替换现有模式，也不是另开独立开关。

这样做的优点是：

1. 用户心智最直接，仍然在“对齐”位置完成选择。
2. 对现有项目结构改动小。
3. 对旧项目兼容成本低。
4. 能准确实现“顶部和底部都对齐，过短拉长，过长压扁”的目标。
