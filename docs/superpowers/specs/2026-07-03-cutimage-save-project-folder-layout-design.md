# CutImage 保存项目目录化设计文档

## 1. 背景

当前“保存项目”在未勾选“保存裁剪图”时，已经会同时输出项目 `json` 和最终拼接图。

但这两个文件会直接落在用户在“另存项目”对话框中选定的外层目录里，导致目录层级过平，不方便整理。

## 2. 目标

本次仅调整“保存项目”的目录语义：

1. 用户在“另存项目”中只选择一个父目录，不再输入项目文件名。
2. 程序按当前项目名自动创建同名文件夹。
3. 项目 `json`、最终拼接图、可选的 `cropped/` 都写入该文件夹内。
4. 项目文件名固定为 `<项目名>.cutimage.json`。
5. “导出结果”行为保持不变，不受本次改动影响。

## 3. 示例

如果用户在保存对话框中选择父目录：

1. `./结果/`

则实际保存结构为：

1. `./结果/实验1/实验1.cutimage.json`
2. `./结果/实验1/实验1.png`
3. `./结果/实验1/cropped/`（仅在勾选“保存裁剪图”时存在）

## 4. 实现设计

在 `./ui/main_window.py` 中增加一个项目保存路径归一化方法：

1. “另存项目”改用目录选择对话框，而不是文件保存对话框。
2. 当用户选定父目录后，程序自动生成 `<项目名>/<项目名>.cutimage.json`。
3. 文件夹名和项目文件名都基于当前项目名自动生成，并做文件名清洗。
4. 已经保存过的项目再次点击“保存项目”时，继续沿用已有项目路径，不自动迁移旧项目。

## 5. 验证点

1. 另存时只选择 `./结果/` 后，产物实际进入 `./结果/实验1/`。
2. 未勾选“保存裁剪图”时，目录中只有项目 `json` 和最终拼接图。
3. 勾选“保存裁剪图”时，目录中额外包含 `./cropped/`。
4. 项目名包含 Windows 非法文件名字符时，保存出的文件夹名和项目文件名仍然合法。
5. “导出结果”目录行为不变。
