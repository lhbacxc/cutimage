# CutImage 最终拼接图清晰度与无损导出设计说明

## 1. 背景

当前工具会在生成最终拼接图时，先按照统一的 `target_height` 对所有裁剪图做缩小重采样，再输出到 `final/combined_result.png`。

这套逻辑有两个直接结果：

1. 最终拼接图的像素尺寸显著小于 `cropped/` 中的单张裁剪图总像素量。
2. 即使最终文件格式是无损 `png`，在进入保存阶段之前，图像细节也已经因为缩小重采样而减少。

现阶段用户的核心诉求不是取消无损压缩，而是区分两类结果：

1. 主结果图应尽量保留原始裁剪图清晰度，不因为最终拼接阶段的统一缩放而损失细节。
2. 仍然保留一份基于 `target_height` 的缩略拼接图，方便查看、分享和延续当前预览逻辑。

同时，导出链路只允许无损压缩，不允许继续保留 `jpg`、`jpeg` 这类有损导出入口。

## 2. 目标

本次设计需要满足以下目标：

1. `final/combined_result.png` 作为默认主结果图，导出时不再按 `target_height` 缩小。
2. 额外生成 `final/combined_result_target_height.png`，继续保留当前按 `target_height` 缩放后的缩略拼接图。
3. 两张最终图共享完全一致的视觉样式参数，仅在尺寸策略上不同。
4. `cropped/` 与 `final/` 的导出链路都只允许无损 `png`。
5. 旧项目若保存过 `jpg`、`jpeg` 配置，重新打开后要自动回退到 `png`，避免遗留有损导出配置继续生效。

## 3. 范围

### 3.1 本次范围

1. 调整最终拼接图的导出行为，改为一次导出两张最终图。
2. 新增“原始分辨率拼接”和“目标高度拼接”两种最终图生成模式。
3. 收紧导出格式限制，只保留 `png`。
4. 兼容旧项目中可能存在的 `jpg`、`jpeg` 输出格式配置。
5. 保持现有预览、项目保存、导出目录复用、增量命名等主要行为的连续性。

### 3.2 暂不纳入范围

1. 将 `cropped/` 目录改为增量命名模式。
2. 新增更多尺寸档位或多档缩略图导出。
3. 将 GUI 中的拼接预览切换为双预览模式。
4. 追求缩略图与原始分辨率图在像素级完全一致。

## 4. 导出行为设计

### 4.1 导出目录结构

导出目录结构保持不变，继续生成以下子目录：

1. `cropped/`
2. `final/`
3. `project/`

本次只调整 `final/` 目录中的最终图产物，不改动整体目录结构。

### 4.2 单张裁剪图导出

`cropped/` 中的单张裁剪图继续沿用现有逻辑导出，但导出格式固定为无损 `png`。

本次不改变其命名规则，仍按原文件名输出，例如：

1. `cropped/IMG_20260511_151503.png`
2. `cropped/IMG_20260511_151733.png`

### 4.3 最终图导出

`final/` 目录改为固定产出两张最终图：

1. `final/combined_result.png`
   作为默认主结果图。
   该图使用原始裁剪尺寸直接拼接，不按 `target_height` 缩小。
2. `final/combined_result_target_height.png`
   作为附带缩略图。
   该图继续使用当前按 `target_height` 缩放后的拼接逻辑。

### 4.4 两张最终图的样式一致性

两张最终图必须共享以下样式参数：

1. 背景色
2. 图片间距
3. 外边距规则
4. 上中下对齐方式
5. 白底细边框
6. 最终图圆角样式与圆角半径

两张图之间唯一允许不同的因素，是单张图进入拼接前是否执行统一缩放。

### 4.5 导出格式限制

导出格式收紧为只允许无损 `png`。

这项约束需要同时体现在：

1. 界面层
2. 设置模型层
3. 底层保存函数

只要有任意一层仍然允许 `jpg`、`jpeg` 流入，就不算完成本次设计目标。

## 5. 渲染流程设计

### 5.1 现状问题

当前最终拼接图生成逻辑只有一种模式：

1. 先取所有裁剪图中的最大高度。
2. 计算统一缩放比例。
3. 将所有图缩放到目标高度附近。
4. 再创建画布并完成排版拼接。

这意味着最终图在导出前已经发生像素信息减少，即便最后保存为 `png` 也无法恢复这些细节。

### 5.2 新的两种拼接模式

最终拼接图生成逻辑需要拆成两种明确模式：

1. 原始分辨率拼接
   不做统一缩放，直接使用每张裁剪图的原始尺寸参与排版。
2. 目标高度拼接
   保留当前逻辑，按 `target_height` 进行统一缩放后再拼接。

### 5.3 共享排版主流程

两种模式应共享同一套排版主流程，避免复制两套大段相似代码。

共享部分包括：

1. 画布背景色计算
2. 外边距计算
3. 图片间距计算
4. 对齐偏移计算
5. 白底细边框绘制
6. 最终图圆角样式处理

### 5.4 分叉点

两种模式只在“单张图进入拼接前的尺寸计算”这一步分叉：

1. 原始分辨率拼接
   直接使用原始裁剪图宽高。
2. 目标高度拼接
   先按 `target_height` 计算缩放后尺寸，再进入后续排版流程。

这样可以保证视觉规则一致，同时把“是否缩小重采样”变成一个清晰、可控的策略参数。

## 6. 代码结构设计

### 6.1 核心图像处理层

建议将 `core/image_processor.py` 中的最终拼接逻辑从“单一 target_height 模式”改造成“带尺寸策略参数的最终拼接函数”。

推荐思路如下：

1. 保留统一的最终拼接主函数。
2. 为该函数增加拼接尺寸模式参数。
3. 在内部根据模式决定是否进行统一缩放。

这样可以避免：

1. 复制一份新的原始分辨率拼接函数。
2. 让原始分辨率版和缩略版在后续维护中出现风格漂移。

### 6.2 导出调用层

`ui/main_window.py` 中的导出流程需要从“生成一张最终图”改为“顺序生成两张最终图”：

1. 先生成主结果 `final/combined_result.png`
2. 再生成缩略图 `final/combined_result_target_height.png`

导出过程中共享同一批已完成的裁剪缓存，避免重复读取和重复检测原图。

### 6.3 预览层

GUI 当前的拼接预览先保持现状，继续代表 `target_height` 版本。

原因如下：

1. 预览区本身就是缩略展示区域。
2. 若直接改成原始分辨率预览，大图缩放到界面中仍然要再次发生显示级缩放，收益有限。
3. 本次目标是修正导出主结果清晰度，而不是重做预览系统。

因此，本次改动中：

1. 导出主结果改为原始分辨率拼接。
2. GUI 预览继续对应缩略拼接图。

## 7. 配置与兼容性设计

### 7.1 输出格式配置收紧

`ProcessingSettings` 中保留 `output_format` 字段，但其有效值范围收紧为仅允许 `png`。

原因如下：

1. 直接删除字段会扩大本次改动范围。
2. 保留字段可以降低对现有项目文件结构的冲击。
3. 通过读取时规范化和保存时写回 `png`，可以逐步清理历史项目配置。

### 7.2 旧项目兼容规则

加载旧项目时，若发现 `output_format` 值为以下任一情况：

1. `jpg`
2. `jpeg`
3. 其他非 `png` 值

则统一规范为 `png`。

后续只要项目再次保存，就应将配置持久化为 `png`，从项目文件层面消除有损导出入口。

### 7.3 界面约束

输出格式选择控件需要移除 `jpg`、`jpeg` 选项，只保留 `png`。

若当前界面状态由旧项目恢复而来，也必须在加载完成后同步显示为 `png`。

### 7.4 底层保存兜底

底层保存函数需要增加兜底校验：

1. 若目标扩展名不是 `png`，则拒绝保存或在进入保存前统一改写为 `png`。
2. 保存参数使用适用于无损 PNG 的路径，不再为 JPEG 预留任何质量参数入口。

本次推荐优先采用“拒绝非 `png` 扩展名”的方式，因为这样更容易尽早暴露异常调用点。

## 8. 命名与增量导出设计

### 8.1 主结果图

主结果图继续沿用现有增量命名规则：

1. 首次导出：`final/combined_result.png`
2. 第二次导出：`final/combined_result_001.png`
3. 第三次导出：`final/combined_result_002.png`

### 8.2 缩略图

缩略图采用独立的基准名，但沿用相同的增量命名规则：

1. 首次导出：`final/combined_result_target_height.png`
2. 第二次导出：`final/combined_result_target_height_001.png`
3. 第三次导出：`final/combined_result_target_height_002.png`

### 8.3 对应关系

一次导出产生的两张最终图应在命名上保持自然配对关系：

1. `combined_result.png`
2. `combined_result_target_height.png`

或：

1. `combined_result_001.png`
2. `combined_result_target_height_001.png`

这样便于用户理解两张图属于同一次导出结果。

## 9. 边界情况

### 9.1 单图项目

即使项目中只有 1 张裁剪图，也仍然导出两张最终图：

1. 原始分辨率单图主结果
2. `target_height` 缩略单图结果

不为单图场景增加特殊分支。

### 9.2 样式像素级差异

两张最终图虽然共享同一套样式规则，但缩略图经过重采样后，以下区域在像素级表现上可能略有差异：

1. 圆角边缘
2. 白底细边框
3. 主体边缘锐利度

这是缩放后的正常视觉差异，不视为样式规则不一致。

### 9.3 非法格式调用

如果未来某个调用点仍试图导出 `jpg`、`jpeg` 或其他格式，应尽快在底层抛出明确错误，而不是默默保存成有损图片。

## 10. 验收标准

完成后至少满足以下标准：

1. `cropped/` 中的单张裁剪图只导出为无损 `png`。
2. `final/combined_result.png` 为主结果图，且不按 `target_height` 缩小。
3. `final/combined_result_target_height.png` 为附带缩略图，继续按 `target_height` 缩放。
4. 两张最终图除尺寸策略外，视觉样式规则一致。
5. GUI 不再允许选择 `jpg`、`jpeg`。
6. 旧项目若带有 `jpg`、`jpeg` 配置，重新打开后会自动回退到 `png`。
7. 主结果图与缩略图都保留现有增量命名能力。
8. GUI 拼接预览继续稳定工作，并保持对应 `target_height` 版本。

## 11. 实施顺序建议

建议按以下顺序实施：

1. 收紧配置模型中的 `output_format` 合法值。
2. 调整 GUI 输出格式控件，只保留 `png`。
3. 改造底层保存函数，增加非 `png` 兜底校验。
4. 改造最终拼接函数，使其支持两种尺寸策略。
5. 调整导出流程，一次生成主结果图与缩略图。
6. 回归验证旧项目加载、增量命名和预览逻辑。

## 12. 非目标说明

本次设计不承诺以下结果：

1. 缩略图在缩小后仍保持与原图完全相同的细节水平。
2. 通过无损压缩消除缩放造成的清晰度变化。
3. 一次性扩展出更多导出尺寸或更多预览模式。

本次解决的问题是：

1. 主结果图不再因为最终拼接阶段的统一缩小而损失清晰度。
2. 缩略拼接图继续保留，满足轻量查看需求。
3. 整个导出链路只允许无损 PNG。
