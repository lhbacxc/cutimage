# 架构说明

## 核心入口

1. `../../app.py`：程序入口，负责创建并运行 `CutImageApp`
2. `../../run_cutimage.bat`：Windows 启动器，负责拉起 GUI

## 主要代码结构

1. `../../core/models.py`
   保存项目数据模型、处理设置和裁剪框结构。
2. `../../core/image_processor.py`
   负责图片读取、自动识别、裁剪、样式处理、拼接和保存。
3. `../../core/project_store.py`
   负责项目文件保存与读取。
4. `../../ui/main_window.py`
   负责 Tkinter 界面、图片列表、单图修正、批量处理、预览刷新和导出交互。

## 关键实现约束

### 中文路径支持

为了避免 Windows 下 OpenCV 直接读取中文路径不稳定，当前图片读取逻辑不使用 `cv2.imread`。

当前做法是：

1. 先使用 `np.fromfile` 读取字节
2. 再使用 `cv2.imdecode` 解码图片

这也是当前支持中文目录、中文文件名和中文项目文件的重要基础。

### 项目恢复策略

项目文件不会额外保存预览图，而是保存裁剪框和相关参数。

打开项目时，再根据这些信息重建缓存和预览。这样可以：

1. 避免冗余预览文件
2. 减少预览图过期风险

### 导出格式限制

当前界面和底层保存逻辑都只允许无损 `png`。

## 关键数据流

主链路可以概括为：

1. 读取源图片
2. 自动识别裁剪区域
3. 用户人工修正
4. 生成单图裁剪结果
5. 拼接为最终图
6. 保存项目或导出结果
